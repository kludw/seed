# Compiler bugs found and fixed (QA pass)

One line each: symptom; cause; fix; regression test (under `tests/`).

1. `P? p, error err = f()` (and `p, err = f()`) gave a non-null `p` holding a zeroed placeholder when `f` failed, for structs, enums, ints, floats, bools, bytes; cause: `genMultiAssign` wrapped the callee's placeholder into a box/`{true, v}` and only nulled targets for `_` discards; fix: every `T?` target beside an error is null (and the part released) when the error is not null; `full/error_nullable_beside`.
2. A field, list element, map entry or mut receiver assigned beside an error (`h.s, err = f()`) was never guarded, so reading it crashed on the null placeholder (segfault on a NULL string); cause: guards only exist for local variables; fix: such targets of a plain `T` are rejected with a hint to use a local; `full/errors/guard_field_target`, `full/errors/guard_mut_receiver`.
3. A variable declared outside an `if`/loop and assigned beside an error inside it could be read after the block without checking the error (segfault); cause: guards were dropped at the end of the block that made them; fix: guards are now a per-path set, copied at branches and joined where paths meet (`checkIf`, `checkFor`, `checkSwitch`, `checkSelect`); `full/errors/guard_outer_if`.
4. Assigning a guarded variable in one branch (or in a loop body, through the pre-loop kill scan) ended the guard on every path; cause: `killAssign` marked the guard dead in place; fix: `assigned`/`endGuard` end it on the current path only, loop scans no longer touch guards; `full/errors/guard_branch_assign`, `full/errors/guard_loop_assign`.
5. A value assigned beside an error at the end of a loop body was read unchecked at the top of the next iteration; cause: no back-edge handling; fix: guards that come around a loop are reported when the next iteration reads the variable before reassigning it (`checkLoopGuards`); `full/errors/guard_loop_back`.
6. `break` on an error left the value beside it readable after the loop; cause: guards did not follow `break`/`continue`; fix: jumps carry the guards of variables outside the loop to the loop's exit (or to the post statement); `full/errors/guard_break`.
7. `n++` on a guarded `n` compiled; cause: `++`/`--` targets go through `checkLvalue`, which skipped the guard check; fix: check the guard in `checkIncDec`; `full/errors/guard_incdec`.
8. After `if (x == null) { return } else { x = null }`, `x` was still narrowed to non-null (segfault); cause: the after-if narrowing ignored assignments in the branch that falls through; fix: re-kill the paths that branch assigns (`scanBlockKills`); `full/errors/narrow_else_assign`. Positive cases: `full/error_guard_paths`.
9. `const int x = two()` (and a local `const` computed from a variable) compiled, although SPEC.md says a constant's value must be computable at compile time; cause: constants were checked as ordinary expressions; fix: `requireConstant` rejects calls of functions/methods/function values, variables, `try`, `group`, channels and mut built-ins; `full/errors/const_call`, `full/errors/const_local_variable`.
10. Calling a constant of function type (`const fn() int f = two` then `f()`) was rejected with "f is a constant, not a function"; cause: `checkGlobalCall` never treated constants as function values; fix: such a call is a function-value call; `full/const_values`.
11. The camelCase hint for a name starting with an acronym was wrong (`HTTPCode` -> "rename it to hTTPCode"); cause: `convertCase` lowercased only the first letter; fix: lowercase the leading capital run (`httpCode`, `url`, `id`); `full/errors/naming_acronym_hint`.
12. A badly named local `const` was reported as "the variable MaxSize"; cause: `declare` used "the variable" for every local; fix: "the constant" for `VarKind.LocalConst`; `full/errors/naming_local_constant`.
13. `case colors.Color.Red:` compiled although `Color` is not pub in package `colors` (`_ = colors.Color.Red` was rejected); cause: `labelNamesDecl` resolved qualified pattern types without the visibility check; fix: report a type that is not pub; `full/errors/pkg_private_enum_pattern`.
14. `for (Node? c = head; c != null; c = c.next)` was rejected ("c is nullable" in the post statement); cause: the post statement was checked after the condition's narrowing scope was closed; fix: check it inside that scope (a body that assigns `c` still kills the narrowing); `full/loop_post_narrowing`, `full/errors/loop_post_narrowing_killed`.
15. Comparing a `T?` with a `T` said only "a nullable value can only be compared with null", at the operator; cause: generic message; fix: name the nullable operand, point at it, and hint `check x != null first`; `full/errors/compare_nullable_operand`.
16. The caret under an error was shifted right on lines with non-ASCII text before the column (one extra space per UTF-8 continuation byte); cause: `Diags.render` emitted one space per byte; fix: continuation bytes take no column; `full/errors/caret_utf8`.
17. Type errors on literals said "cannot use the value (type string) as int"; cause: `Ast.exprText` had no text for literals; fix: short literals are described as written (`"7"`, `-1`, `'x'`, `null`), composite literals as `[]int{...}`, `P{...}`; `full/errors/literal_in_message`, `full/errors/list_literal_in_message`.
18. `m["a"]++` compiled to invalid C (`sd_list_at_mut` on a map); cause: `checkIncDec` accepted a map entry as a place, and `genIncDec` only knows list places; fix: reject `++`/`--` on a map entry (the key may be missing) with a hint to read, check and assign; `full/errors/map_entry_incdec`.
19. `ch.send(true)`, `bs.contains(false)`, `bs.index(true)` and sending `null` on a `chan error` generated invalid C (`&true`, `&SD_IFACE_NULL`); cause: `Gen.addr` took the address of anything that looked like a C identifier; fix: only variables (`l_`) and temporaries (`_t`) are addressed directly, anything else is copied first; `full/literal_operands`, `full/select_struct_float`.
20. `string?? x = null` was reported as "expected the end of the statement, found '?'" with the hint "put one statement per line"; cause: `scanType` did not see `T??` as the start of a declaration, so the parser's own "T?? is not a valid type" check was never reached; fix: scan `T??` as a type and report it (with a hint) in `parseType`; `full/errors/double_nullable`.
21. The hint for `map[string](string?)` read "m[k] already returns string??, which would be string??"; cause: the hint applied `?` to the already-nullable value type twice; fix: "m[k] already returns string? (null for a missing key) ..."; `full/errors/map_nullable_value`.
22. Mutating an element of a parameter said "cannot call the mut method push() on the value"; assigning to the receiver of a non-mut method said only "parameters are read-only"; cause: `requireMutable` used the generic description; fix: "an element of rows", and the receiver case says the method is not mut; `full/errors/param_element_message`, `full/errors/receiver_not_mut`.
23. `return null, err` for a plain result (`(string, error)`) when `err` was null handed the caller a null string it could read after `err == null` (segfault); `return null, null` even compiled; cause: a `null` in a plain result slot beside an error was accepted unconditionally; fix: the checker rejects it when the error is the literal `null` or known to be null, and the generator traps the remaining case at the `return` (`crash: f returned null as result 1 without an error`); `full/errors/return_null_null`, `full/return_null_without_error`.
24. `string s, error err = f()` then `t, err = g()` and `if (err != null) { return err }` made `s` readable although `f` had failed (segfault); cause: a guard was satisfied by any later null check of the same variable, even after it was reassigned; fix: assigning the error variable marks the guards waiting for it as lost (`Guard.lost`), with a message saying the error was replaced before it was checked; `full/errors/guard_error_reassigned`.
25. The hint for a pattern of another package's enum wrote the field types as that package spells them (`geo.Shape.At(Point p, ...)`, which does not compile in the user's package); cause: `casePattern` printed the declaration's type expressions; fix: print the resolved types (`geo.Point`); `full/errors/pkg_pattern_hint`.
26. `switch (p.name) { case p.bump(): ...` read the switch value after the mut label had freed it (heap-use-after-free under ASan); cause: `genSwitch` borrowed the value; fix: a value switch keeps its own copy when a label has mut effects; `full/switch_label_effects`.
27. All labels of a `case` were evaluated before comparing (`case "w0", word(10):` called `word(10)` even when the first label matched); cause: the labels were joined into one `||` of precomputed values; fix: when a later label has side effects, labels are tried in order; `full/switch_label_effects`.
28. A value-switch label that is a call without arguments (`case p.bump():`, `case cfg.name():`) was parsed as an enum pattern and rejected ("string is not an enum, so case patterns with bindings cannot be used"); cause: `parseLabel` treats `X.Y()` as a pattern only; fix: such a label keeps its expression too, and a value switch uses it; also loop kill scans and loop guard reads now include labels; `full/switch_label_effects`.
29. A local, parameter, function or constant could be named `int`, `float`, `string`, ... (`string float = "x"` then `float(2)` failed with "float is a variable of type string, not a function"); cause: built-in type names are identifiers and nothing reserved them; fix: such names are rejected where they are declared; `full/errors/builtin_type_name`.
30. A map literal could list the same literal key twice (`{"b": 2, "b": 3}`), silently keeping the last; cause: no check; fix: duplicate literal keys are reported; `full/errors/map_literal_duplicate_key`.
31. A second package-level declaration said "f is already declared at /full/path/x.sd:15:4" (and had no hint); cause: always printed the full path; fix: "at line 15" in the same file, the path only for another file, with a hint; `full/errors/duplicate_function`.
32. Deeply nested code crashed the compiler with "crash: stack overflow" (2000 nested parentheses, a 2500-term sum, 3000 nested ifs; `seed fmt` and `seed ast` too), and around 600 levels the generated C crashed clang; cause: every phase recurses over the tree without a limit; fix: the parser rejects blocks and expressions nested more than 256 levels deep (`Parser.enter`, tree depth in `Parser.addExpr`) with a hint to split the code; `full/errors/nested_too_deeply`.
33. `'\x'` reported both "\x needs two hex digits" and "a byte literal must hold exactly one byte"; cause: the byte count was checked after a failed escape; fix: skip it after a bad escape; `full/errors/byte_bad_escape`.
34. `if (m["k"] != null) { m["k"].len() }` was rejected with the hint "check the value != null before calling len()", which the code already does; cause: only variables and field paths are narrowed, and the hint did not say so; fix: for anything else the hint says to store it in a variable first and shows the code (`string? v = m["k"]`); `full/errors/nullable_element_hint`.
35. A parameter named like the receiver or another parameter got the hint "assign with = instead"; cause: `declare` used the hint for locals everywhere; fix: say which declaration it clashes with (a parameter, the receiver) and suggest different names; `full/errors/param_receiver_same_name`.
36. `if (a < b < c) {` reported the chained comparison, then a bogus "unexpected end of file: missing '}'" (or "expected fn, type, const or test at the top level"); cause: after the error inside the parentheses, `syncStatement` counted the `)` as closing a bracket it had not seen, went below depth 0 and stopped after the `{`, so the `}` of the `if` closed the function; fix: `syncStatementFrom` starts from the brackets the statement opened before the error and only stops at a newline when they are all closed; `core/errors/chain_compare_recovery`, `core/errors/chain_compare_args` (with `// expect-errors: 1`, a new check of `tests/run.sh`).
37. The hint for `return null, null` read "return a int value"; cause: the article was written as "a"; fix: `withArticle` ("an int", "an error", "a string", "a User"); `full/errors/return_null_hint`, `full/errors/return_null_hint_struct`.
38. `fn float(...)` was reported as a built-in type name, and each call `float(x)` then failed again as a conversion ("cannot convert string to float", "the conversion string() takes exactly one argument"), a use as a value as "undefined: float", and a call of a local `string float` as "float is a variable of type string, not a function"; cause: the rejected declaration left the name unresolved; fix: the checker remembers package-level names rejected that way (`Checker.builtinNamed`) and reports nothing more for their uses; `full/errors/builtin_name_function`, `full/errors/builtin_type_name` (with `// expect-errors:`).
