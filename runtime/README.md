# The Seed runtime

The C runtime that programs generated by the Seed compiler include. It
replaced the runtime of the retired bootstrap compiler seed0 (64-bit ints,
memory never freed) with:

- integers that grow (tagged 64-bit words, big integers on the heap),
- reference counting with value semantics (copy-on-write) for strings, lists,
  maps and boxes, driven by **type descriptors** that generated code supplies,
- goroutines on OS threads, channels, `select`, groups with Erlang-style
  failure, timers,
- blocking calls that are stop points (`sd_wait_fd`, `sd_wait_child`) and
  the process-wide handle table that `io`, `net` and `fs` use,
- per-goroutine crash handling and a defer stack,
- interface values, `error`, the OS side of the core packages `fmt`, `os`,
  `fs`, `errors` and `time` (the packages themselves are in `lib/`, with
  native functions that call these; see [Native functions](#13-native-functions)),
- the runner of `seed test` programs.

This file is the reference for the code generator. `seed.h` has the same
information in shorter form; `tests/example.c` is a complete hand-lowered
program that follows every rule below.

## 1. Building

```
runtime/seed.h           the API (include it FIRST in generated C: it sets the POSIX feature macros)
runtime/seed_internal.h  shared by the implementation only
runtime/seed_core.c      allocation, type descriptors, boxes, interfaces, errors
runtime/seed_int.c       big integers
runtime/seed_str.c       strings and text conversions
runtime/seed_list.c      lists and maps
runtime/seed_task.c      goroutines, crashes, defer, groups, channels, select, timers, sd_main
runtime/seed_pkg.c       the OS side of fmt, os, fs (called by the natives in lib/)
runtime/seed_test.c      the runner of seed test programs, assert errors
runtime/seed_all.c       all of the above as one translation unit
```

```
cc -std=c11 -O2 -I runtime prog.c runtime/seed_all.c -lpthread -lm -o prog
```

The `seed_*.c` files can also be compiled separately (or into a static
library). To embed the runtime in one generated file, paste `seed.h`,
`seed_internal.h` and the seven `.c` files in that order, dropping their
`#include "seed*.h"` lines.

The runtime is C11 plus POSIX threads and two GNU extensions that clang and
gcc accept in `-std=c11`: `__builtin_*_overflow`, and statement expressions in
the `SD_STR_LIT` and `SD_INT_BIGLIT` macros. It builds warning-free with
`-Wall -Wextra`. Compile-time options:

| Macro | Effect |
|---|---|
| `SD_COUNT_OBJECTS` | Count live heap objects (`sd_live_objects()`); the tests use it to find leaks. |
| `SD_GOROUTINE_STACK` | Stack size of goroutine threads in bytes (default 8 MB). |

## 2. Representation of every Seed type

All names are C identifiers from `seed.h`.

| Seed | C type | Null (`T?`) | Counted? |
|---|---|---|---|
| `int` | `sd_int` (a struct holding one tagged `int64_t` word) | `SD_INT_NULL` | big values only |
| `float` | `double` | `sd_opt_float {bool has; double v}` | no |
| `bool` | `bool` | `sd_opt_bool` | no |
| `byte` | `uint8_t` | `sd_opt_byte` | no |
| `string` | `sd_str` = `sd_string *` | `NULL` | yes |
| `[]T` | `sd_list *` | `NULL` | yes |
| `map[K]V` | `sd_map *` | `NULL` | yes |
| `chan T` | `sd_chan *` | `NULL` | yes (atomic) |
| struct `S` | a C struct, by value | `sd_box *` holding an `S` | its fields |
| enum `E` | recommended: `sd_box *` holding an enum struct (below) | `NULL` | yes |
| interface `I` | `sd_iface {vt, obj}` | `vt == NULL` | `obj` is a box |
| `error` | `sd_err` (= `sd_iface`) | `vt == NULL` (always nullable) | `obj` is a box |
| `fn(A) R` | a C function pointer `R (*)(A)` | `NULL` | no |
| several results | a generated struct, or out-parameters | | |

Details:

- **int**: `w & 1 == 0` means a small integer with value `w >> 1` (63-bit
  range, `-2^62 .. 2^62-1`); `w & 1 == 1` means `(sd_bigint *)(w - 1)`; `w == 1`
  is `SD_INT_NULL`. Values are normalised (a value that fits is always small),
  so equality of two small words is word equality. Write constants with
  `SD_INT(42)`; constants outside the small range with `SD_INT_BIGLIT("...")`.
  `int?` is just an `sd_int` that may be `SD_INT_NULL`.
- **string**: a counted, immutable, NUL-terminated byte array with its length
  (`s->len`, `s->data`). Bytes may include `\0`. Literals are static
  immortal objects (`SD_STR_LIT("...")`), as are `""` and all one-byte strings.
- **[]T**: one allocation: a header (`rc`, `len`, `cap`, element descriptor
  `et`) followed by `len` elements of C type `T`, unboxed. `[]int` stores
  `sd_int`s, `[]User` stores `S_User` structs, `[]string?` stores `sd_str`s
  (some NULL), `[]float?` stores `sd_opt_float`s.
- **map[K]V**: an insertion-ordered hash map. Keys are `int`, `byte`, `bool`
  or `string`, stored as their C representation; values are stored unboxed.
  The map remembers its key and value descriptors.
- **struct**: a plain C struct, copied by value; counted fields make it a
  "counted" type that needs retain/release on copy/drop (via its descriptor
  or inline code).
- **S?** (nullable struct) and recursive types (`Node? next`): `sd_box *`, a
  counted heap cell `{rc, type}` followed by the value. Boxes are
  copy-on-write like lists.
- **enum**: recommended layout is a C struct whose first member is
  `int32_t tag`, followed by a union of per-case payload structs, described
  by an `SD_K_ENUM` descriptor (section 4), and held in an `sd_box *`. Cases
  without data can be static immortal boxes (`SD_BOX_STATIC`), so they never
  allocate. (Holding enums by value is also supported by the descriptor; boxing
  is what makes recursive enums possible.)
- **interface / error**: `{const sd_vtable *vt; sd_box *obj}`. `obj` holds the
  dynamic value; `obj->t` is its type. See section 8.
- **chan T**: shared between goroutines, so its count is atomic. Elements are
  deep-copied on send (section 11).
- **function values**: plain C function pointers; Seed has no closures.

## 3. Ownership rules

Every counted value has a reference count. The rules are the same for every
type; only the retain/release function differs (`sd_str_retain`,
`sd_list_release`, `sd_int_retain`, ..., or `sd_retain(&T, &v)` for any type).
For non-counted types (float, bool, byte, fn, trivial structs) they are no-ops
and can be omitted.

**Owned** means "this reference holds one count and must eventually be
released or moved". **Borrowed** means "valid for now, not to be released".

| Situation | Rule |
|---|---|
| Local variable | Owns its value. Release it when it goes out of scope, unless it was moved out (returned). |
| Function parameter | **Borrowed.** The callee never releases a parameter. If it stores it somewhere or returns it, it retains first. |
| Function result | **Owned** (+1). Every runtime function and every generated function returns owned values. |
| Runtime arguments | **Borrowed**, except the stored value of `push`, `insert`, `set`, `sd_map_set` (key and value), `sd_box_new`, `sd_iface_new` and `sd_str_append`'s first argument, which are **consumed** (ownership moves into the container; don't release them afterwards). |
| Pointers returned by `SD_LIST_GET`, `sd_list_at_mut`, `sd_map_get`, `sd_map_get_mut`, `sd_box_data`, `sd_iface_self` | **Borrowed**, valid until that container is next modified or released. |
| `x = e` | Evaluate `e` to an owned value; release the old `x`; store. (Release after evaluating, since `e` may read `x`.) |
| `y = x` (copy from a place) | Retain: `y = sd_list_retain(x)`. A struct copy retains each counted field: `sd_retain(&T_S, &y)` after the byte copy. |
| `return x` for a local `x` | Move: no retain, and don't release `x`. |
| `return p` for a parameter or field | Retain (it's borrowed). |
| Temporaries | Results of calls are owned temps; release them after their last use in the statement. |
| Struct literal `S{a: e1, b: x}` | Each field takes an owned value: temps move in, places are retained. |
| Literal strings, `SD_INT(...)`, `SD_INT_BIGLIT`, `SD_STR_LIT` | Immortal or uncounted: owned and borrowed at the same time; retain/release are no-ops. |

Copy-on-write: a container is modified in place only when its count is 1.
Every mutating runtime function takes a **place** (`sd_list **`, `sd_map **`,
`sd_box **`) and, when the container is shared, replaces `*place` with a
private copy first (the copy retains the elements; the original loses one
count). This is what makes `[]int b = a; b.push(1)` leave `a` alone.

Multiple results: runtime functions with several results return the `error`
and write the other results through out-pointers (owned). When the error is
not null, the outputs hold their null value (`NULL`, `SD_INT_NULL`) or zero
(`double`), which need no release. Generated functions may do the same or
return a struct; the runtime doesn't care.

Goroutines share nothing, so plain (non-atomic) counts are safe: everything a
goroutine can reach was created by it or deep-copied for it. The only objects
shared between threads are channels (atomic count) and immortal objects
(never counted).

## 4. Type descriptors

Containers, boxes, channels and `spawn` handle values of any type through an
`sd_type` descriptor: its C size, and how to retain, release, deep-copy and
compare it. The runtime provides descriptors for the built-in types:

| Seed type | Descriptor |
|---|---|
| `int`, `int?` | `sd_type_int` |
| `float`, `bool`, `byte` | `sd_type_float`, `sd_type_bool`, `sd_type_byte` |
| `float?`, `bool?`, `byte?` | `sd_type_opt_float`, `sd_type_opt_bool`, `sd_type_opt_byte` |
| `string`, `string?` | `sd_type_str` |
| any `[]T`, `[]T?` | `sd_type_list` (a list knows its own element type) |
| any `map[K]V` | `sd_type_map` |
| any boxed value (`S?`, enums) | `sd_type_box` (a box knows its own type) |
| any `chan T` | `sd_type_chan` |
| interfaces | `sd_type_iface` (equal: same dynamic type and equal values) |
| `error` | `sd_type_err` (equal: both null, or same `message()`) |
| any `fn(...)` | `sd_type_fn` |

Generated code defines one descriptor per struct, per enum, and per
spawn-argument struct, normally as a field table (no code needed):

```c
typedef struct { sd_str f_name; sd_list *f_tags; sd_int f_age; double f_score; } S_User;
static const sd_field F_User[] = {
  SD_FIELD(S_User, f_name, &sd_type_str),
  SD_FIELD(S_User, f_tags, &sd_type_list),
  SD_FIELD(S_User, f_age, &sd_type_int),
  SD_FIELD(S_User, f_score, &sd_type_float),
};
static const sd_type T_User = SD_STRUCT_TYPE("User", S_User, F_User);
```

Use `SD_STRUCT_TYPE_TRIVIAL` when no field is counted (retain/release become
no-ops and deep copy is a `memcpy`). Fields of nested struct type point at
that struct's descriptor; fields of type `S?` use `sd_type_box`.

Enums (tag first, `int32_t`, indexing the variants array):

```c
typedef struct {
  int32_t tag;
  union { struct { double r; } Circle; struct { double w, h; } Rect; struct { sd_str n; } Named; } u;
} E_Shape;
enum { Shape_Circle, Shape_Rect, Shape_Named, Shape_Empty };
static const sd_field F_Circle[] = {SD_FIELD(E_Shape, u.Circle.r, &sd_type_float)};
static const sd_field F_Rect[] = {SD_FIELD(E_Shape, u.Rect.w, &sd_type_float), SD_FIELD(E_Shape, u.Rect.h, &sd_type_float)};
static const sd_field F_Named[] = {SD_FIELD(E_Shape, u.Named.n, &sd_type_str)};
static const sd_variant V_Shape[] = {{"Circle", F_Circle, 1}, {"Rect", F_Rect, 2}, {"Named", F_Named, 1}, {"Empty", NULL, 0}};
static const sd_type T_Shape = SD_ENUM_TYPE("Shape", E_Shape, V_Shape);
SD_BOX_STATIC(Shape_Empty_box, &T_Shape, E_Shape, {.tag = Shape_Empty});   /* Shape.Empty == SD_BOX_REF(Shape_Empty_box) */

sd_box *mk = sd_box_new(&T_Shape, &(E_Shape){.tag = Shape_Circle, .u.Circle = {2.0}});
```

`SD_K_CUSTOM` descriptors supply `retain`, `release`, `clone_deep` and `equal`
functions instead, for anything the tables can't describe.

The generic operations `sd_retain`, `sd_release`, `sd_clone_deep`, `sd_equal`
work on any descriptor; generated code may call them for struct copies and
drops and `==` on structs, or emit field-by-field code for speed.

## 5. Integers

```c
sd_int a = SD_INT(40);                                   /* |constant| < 2^62 */
sd_int b = SD_INT_BIGLIT("1267650600228229401496703205376"); /* cached, immortal */
sd_int c = sd_int_add(a, b);                             /* owned */
...
sd_int_release(c);
```

- Operations: `sd_int_add sub mul div mod neg and or xor shl shr` (arguments
  borrowed, result owned), `sd_int_eq ne lt le gt ge cmp`. The small/small case
  is inline and takes a few instructions; the rest goes to `seed_int.c`.
- `/` and `%` truncate toward zero (`-7 / 2 == -3`, `-7 % 2 == -1`) and crash
  with `division by zero`.
- `& | ^` use infinite two's complement for negatives; `>>` floors
  (`-5 >> 1 == -3`). A negative shift count crashes (`negative shift count`).
  `<<` by more than 2^32 bits of a non-zero value crashes (`shift count too large`).
- Conversions: `sd_int_to_float` (nearest double, correctly rounded),
  `sd_float_to_int` (truncates; crashes on nan/inf: `cannot convert float nan
  to int`), `sd_int_to_byte` (crashes unless 0..255: `cannot convert 300 to
  byte`), `sd_byte_to_int`, `sd_int_to_str`, `sd_str_to_int`.
- Indexing: `sd_int_index(i, len)` returns the `int64_t` index or crashes with
  `index out of range: <i> with length <len>`.
- `for (int i = 0; i < n; i++)` lowers naturally: `i` is an `sd_int`;
  `i++` is `t = sd_int_add(i, SD_INT(1)); sd_int_release(i); i = t;` (both
  calls are a few instructions for small values; see section 15).
- byte: arithmetic is not defined on bytes; comparisons and `& | ^` are
  plain C; shifts use `sd_byte_shl`/`sd_byte_shr` (8 or more gives 0).

## 6. Strings

Strings are immutable. Every method returns an owned string (often the same
object, retained, when nothing changes). Indexes and lengths are bytes.

```c
sd_str s = SD_STR_LIT("hello");                    /* literal: immortal */
sd_str t = sd_str_concat(s, name);                 /* s + name */
sd_str parts[] = {a, SD_STR_LIT(" "), b, c};
sd_str u = sd_str_concat_n(parts, 4);              /* a + " " + b + c, one allocation */
acc = sd_str_append(acc, piece);                   /* acc = acc + piece: consumes acc; amortised O(1) when unshared */
```

Use `sd_str_append` for `x = x + e` when `x` is a local, so building a string
in a loop is linear. `SD_STR_LIT` works inside functions; for file scope use
`SD_STR_STATIC(name, "text")` and `SD_STR_REF(name)`. `sd_str_cstr(s)` gives
the NUL-terminated bytes (borrowed).

`float.string()` is the shortest text that reads back as the same double,
fixed notation when the decimal exponent is in `-4 .. 15`, otherwise
`1e+300` style, always with a `.` or an `e`; `nan`, `inf`, `-inf`. It is
byte-for-byte identical to seed0's (the tests check 20,000 random values
against seed0's implementation, kept in `tests/ref_float.c`).

## 7. Lists, maps, boxes and copy-on-write

```c
sd_list *xs = sd_list_new(&sd_type_int, 0);           /* []int{} */
SD_LIST_PUSH(&xs, sd_int, SD_INT(1));                  /* xs.push(1): consumes the value */
sd_int v = sd_int_retain(SD_LIST_GET(xs, sd_int, i));  /* int v = xs[i] (borrowed read, then retain) */
sd_list_set(&xs, i, &(sd_int){...});                   /* xs[i] = e (consumes; releases the old element) */
```

`SD_LIST_GET(l, T, i)` is an lvalue of type `T` (read only) with the bounds
check; `i` is an `sd_int`. `SD_LIST_PUSH(pl, T, v)` is the inline fast path of
`sd_list_push(pl, &v)`. Both macros evaluate `l`/`pl` more than once (and `v`
exactly once), so pass a variable or a side-effect-free place expression
(`&u->f_tags`), never a call.

**Mutation through a path.** A mut method or assignment on `a.b[i].c` takes a
pointer to the place, making every container on the way unique:

```c
/* users[2].tags.push(t) */
S_User *u = sd_list_at_mut(&l_users, SD_INT(2));   /* unique users; pointer to element 2 */
SD_LIST_PUSH(&u->f_tags, sd_str, sd_str_retain(l_t));
/* u.tags.push(t) with u a local struct */
SD_LIST_PUSH(&l_u.f_tags, sd_str, sd_str_retain(l_t));
/* m[k].push(x) (map of lists) */
sd_list **pl = sd_map_get_mut(&l_m, &key);        /* NULL if absent */
/* node.next.value = 5 with Node? next (a box) */
S_Node *n = sd_box_mut(&l_node.f_next);
```

A mut method receives `T *self` (a pointer to the place). Evaluate the
method's arguments before computing the receiver's place, and retain them,
because the call may change what they point into (`bag.addAll(bag)`).

**Values passed to stores must not point into the container being changed**
in generated code (pass a pointer to a temporary). The runtime copies the
value first anyway, so `xs.push(xs[0])` is safe even if you forget.

Lists: `pop` moves the last element into `*out` and returns false when empty
(lower `T? x = xs.pop()` accordingly). `index`/`str_index` return `int?` as
`SD_INT_NULL` when absent. `sort` handles `[]int`, `[]float`, `[]string`,
`[]byte`. `sortBy(f)` takes an adapter, because the runtime can't call a Seed
function of unknown type:

```c
static bool less_User(void *ctx, const void *a, const void *b) {   /* one per element type */
  bool (*f)(S_User, S_User) = (bool (*)(S_User, S_User))ctx;
  return f(*(const S_User *)a, *(const S_User *)b);
}
sd_list_sort_by(&l_people, less_User, (void *)l_f);   /* stable */
```

Maps: keys and values are passed by pointer.

```c
sd_map *m = sd_map_new(&sd_type_str, &sd_type_int);          /* map[string]int{} */
sd_map_set(&m, &key, &val);         /* m[k] = v: consumes key and val */
sd_int *p = sd_map_get(m, &key);    /* m[k] as int?: */
sd_int r = p ? sd_int_retain(*p) : SD_INT_NULL;
sd_map_delete(&m, &key);
sd_list *ks = sd_map_keys(m);       /* []K in insertion order */
int64_t pos = 0; void *k, *v;
while (sd_map_next(m, &pos, &k, &v)) { ... }   /* iteration, borrowed */
```

Replacing a value keeps the key's position; a deleted key that is added again
goes to the end. Map equality ignores order.

Boxes: `sd_box_new(&T, &val)` (consumes `val`), `SD_BOX_GET(b, T)` to read,
`sd_box_mut(&b)` to get a writable pointer (copy-on-write).

## 8. Interfaces, errors and function values

A vtable is a generated struct whose first member is `sd_vtable`, followed by
one function pointer per method. Methods take `const void *self` (a borrowed
pointer to the payload inside the box) and follow the normal ownership rules:

```c
typedef struct { sd_vtable hdr; double (*area)(const void *self); sd_str (*name)(const void *self); } VT_Shape;
static double Square_area_i(const void *self) { return sd_m_Square__area(*(const S_Square *)self); }
static sd_str Square_name_i(const void *self) { return sd_m_Square__name(*(const S_Square *)self); }
static const VT_Shape VT_Square_Shape = {{"Square"}, Square_area_i, Square_name_i};

sd_iface s = sd_iface_new(&VT_Square_Shape.hdr, &T_Square, &(S_Square){2.0});  /* Shape s = Square{side: 2.0} */
double a = ((const VT_Shape *)s.vt)->area(sd_iface_self(s));                      /* s.area() */
```

`error` uses the fixed layout `sd_error_vtable {sd_vtable hdr; sd_str
(*message)(const void *self);}`. A user type that `implements error` provides
one; `errors.new` uses `sd_errors_vtable` with a boxed string.

```c
sd_err e = sd_errors_new(msg);          /* errors.new(msg) (msg borrowed) */
sd_err f = sd_errorf("x: %s", "y");     /* runtime-made errors */
sd_str m = sd_err_message(e);           /* e.message(): owned; crashes if e is null */
if (!sd_err_is_null(e)) ...             /* e != null */
sd_err_release(e);
```

`==` on interfaces: `sd_iface_equal` (same dynamic type and equal payloads).
`==` on errors: `sd_err_equal` (both null, or the same message; this is seed0's
rule).

Function values are C function pointers. A list of them uses `sd_type_fn`.

## 9. Crashes and defer

`sd_crash(fmt, ...)` crashes the current goroutine. The runtime crashes on
the faults in builtins.md (index out of range, division by zero, failed
conversions, send on a closed channel, ...), and on a stack overflow or
other memory fault (`stack overflow or invalid memory access`). What
happens next:

1. The goroutine's pending defers run, newest first (and any groups it
   started are stopped and waited for, in stack order).
2. In a goroutine inside a group, the crash becomes the group's error,
   `crash: <message>`. In the main goroutine, the program prints
   `crash: <message>` to stderr after flushing stdout and exits with code 2.

Crash unwinding is a `siglongjmp` to the goroutine's top frame, so generated
code needs no checks after calls. The cost is that **the counted values held
by the unwound C frames' locals are not released** (they leak). Defer thunks
own their environments, so those are released normally. This is the main
known limitation; see section 16.

**Defer API.** A function containing `defer` records the stack depth on entry
and unwinds to it before every return:

```c
/* fn work(string path) error { defer fmt.println("done: " + path) ... } */
typedef struct { sd_str a0; } D1_env;                 /* the evaluated arguments */
static void D1_thunk(void *p) {                       /* runs the call, releases the env */
  D1_env *e = p;
  sd_fmt_println(e->a0);
  sd_str_release(e->a0);
}

static sd_err sd_f_work(sd_str l_path) {
  size_t dmark = sd_defer_mark();
  {
    D1_env env = {sd_str_concat(SD_STR_LIT("done: "), l_path)};   /* arguments are evaluated now */
    sd_defer_push(D1_thunk, &env, sizeof env);                     /* bytes are copied */
  }
  ...
  if (failed) { sd_err r = ...; /* release locals */ sd_defer_run(dmark); return r; }
  ...
  sd_defer_run(dmark);       /* before EVERY return, after computing the result */
  return SD_ERR_NULL;
}
```

Rules:

- Evaluate the deferred call's arguments (and receiver) at the `defer`
  statement into an owned env; the thunk calls the function and releases
  the env. An env may be empty (`sd_defer_push(thunk, NULL, 0)`).
- Compute the return values first (they may read locals), then release the
  locals, then `sd_defer_run(mark)`, then return. `try` is a return like any
  other. Functions without `defer` need no mark.
- A crash inside a deferred call during normal return turns into a crash of
  the goroutine; the remaining defers still run. A crash inside a deferred
  call while already unwinding is contained: the next defer still runs, and
  the first crash message is the one reported.
- `os.exit` exits immediately without running defers (like Go).
- `sd_catch(fn, arg)` runs `fn(arg)` in a protected frame and returns a crash
  as an error `crash: <message>`. The language doesn't need it today; the
  tests use it, and `seed test` can use it to run each test.

## 10. Goroutines, groups and spawn

Each goroutine runs on an OS thread of its own (8 MB stack by default);
threads are kept and reused by later goroutines (worker threads, below). A
`group` block is lowered to `sd_group_begin`, one `sd_spawn` per `spawn`
statement (which may be inside loops or ifs in the block), and
`sd_group_wait`:

```c
/* fn worker(int id, []Item items, chan string out) error */

/* One argument struct, descriptor and trampoline per spawned function: */
typedef struct { sd_int a0; sd_list *a1; sd_chan *a2; } A_worker;
static const sd_field F_A_worker[] = {
  SD_FIELD(A_worker, a0, &sd_type_int), SD_FIELD(A_worker, a1, &sd_type_list), SD_FIELD(A_worker, a2, &sd_type_chan)};
static const sd_type T_A_worker = SD_STRUCT_TYPE("spawn worker", A_worker, F_A_worker);
static sd_err G_worker(void *p) {
  A_worker *a = p;                       /* the goroutine's private copy; borrowed */
  return sd_f_worker(a->a0, a->a1, a->a2);
}

/* error err = group { spawn worker(1, items, out); spawn worker(2, other, out) } */
sd_err l_err;
{
  sd_group *g = sd_group_begin();
  { A_worker a = {SD_INT(1), l_items, l_out}; sd_spawn(g, G_worker, &T_A_worker, &a); }  /* borrowed */
  { A_worker a = {SD_INT(2), l_other, l_out}; sd_spawn(g, G_worker, &T_A_worker, &a); }
  l_err = sd_group_wait(g);              /* owned; g is freed */
}
```

- `sd_spawn` deep-copies the arguments (through the descriptor) into memory
  owned by the new goroutine, so the spawning goroutine keeps its own values
  and nothing is shared. Channels are shared, not copied. The runtime
  releases the copy when the goroutine ends. A goroutine with no arguments:
  `sd_spawn(g, G_f, NULL, NULL)`.
- The trampoline returns the function's error (owned). If a spawned function
  returns other values too, the trampoline releases them.
- Code in the group block other than `spawn` runs normally in the parent.
  Don't `return` from inside a group block without `sd_group_wait` (the
  compiler forbids `return`, `try` and `break`/`continue` out of a group
  block); if it happens anyway, `sd_defer_run` stops and waits for the
  group.
- **Failure.** When a goroutine returns an error or crashes, the group records
  the first error and cancels every other goroutine in it. A cancelled
  goroutine stops at its next **stop point** (a channel send, receive or
  select, `time.sleep`, or a blocking call of section 13: reading,
  accepting, connecting, waiting for a child), or immediately if it is
  blocked in one; its defers run.
  `close` is not a stopping point (so `defer out.close()` works in a stopped
  goroutine). A `spawn` executed after the group has failed doesn't start the
  goroutine. `sd_group_wait` returns the first error (`crash: <message>` for a
  crash), or null.
- **Finished goroutines are freed while the group runs.** A goroutine that
  ends moves itself to its group's dead list (its last use of its task);
  the next `sd_spawn` in the group (or `sd_group_wait`) frees those tasks.
  A server's group, which spawns a goroutine per connection for as long as
  it runs, so holds only the connections that are open.
- **Worker threads.** `sd_spawn` hands the goroutine to an idle worker
  thread if there is one, and creates a thread otherwise. A worker whose
  goroutine returned (with an error or not) waits for the next one,
  spinning for up to 20 us and then on a condition variable; it ends after
  2 s without work, or at once when 1024 workers are idle. A worker whose
  goroutine crashed or was stopped ends instead of being reused, so that
  thread-local state a crash may have left half-made (a package constant
  being computed, `seed_core.c`'s free queue) never reaches another
  goroutine. Thread-local caches that live longer than a goroutine must be
  released or reset by an `sd_goroutine_atexit` function, which runs at
  the end of every goroutine (the generated constant caches and `rand`'s
  generator do this).
- **Nesting.** A goroutine may run its own groups. Cancelling a goroutine that
  is waiting in `sd_group_wait` cancels that inner group too, so whole trees
  stop. A group is always waited for: if the goroutine that owns it crashes
  or is cancelled, the runtime cancels the group and waits for it before
  running the defers registered before it.
- **Deadlock detection.** When every goroutine is blocked on a channel or a
  group and no timer is pending, the program prints `crash: deadlock: all
  goroutines are blocked` and exits with code 2 (instead of hanging).
- Crashes in the main goroutine (including in a group block) end the program
  as in section 9, after stopping and waiting for its groups.

## 11. Channels, select and time

```c
sd_chan *c = sd_chan_new(&sd_type_str, SD_INT(10));  /* chan string(10); 0 = unbuffered */
sd_chan_send(c, &l_s);                               /* c.send(s): s borrowed */
sd_str l_v;                                          /* string? v = c.receive() */
if (!sd_chan_receive(c, &l_v)) l_v = NULL;           /* false: closed and empty */
sd_chan_close(c);                                    /* crashes if already closed */
sd_chan_release(c);
```

- **Copies.** The receiver always gets a deep copy made for it (strings,
  lists, maps, boxes, big integers are copied; immortal objects and
  channels are shared). The copy is made exactly once, under the channel
  lock: into the buffer, or directly into a waiting receiver's variable.
  The value you send stays yours (send borrows it).
- Send on a closed channel crashes (`send on closed channel`); so does
  closing twice (`close of closed channel`). Receive on a closed channel
  returns the buffered values, then false.
- Unbuffered channels are rendezvous: the sender waits for a receiver.

**select** is lowered to an array of cases and a `switch` on the result:

```c
/* select {
 * case int? n = results.receive(): A
 * case jobs.send(j):               B
 * case time.after(5 * time.second).receive(): C
 * } */
sd_int l_n, t_tick;
sd_chan *t_timer = sd_time_after(SD_INT(5000000000));
sd_select_case cs[3] = {
  {l_results, SD_RECV, &l_n, false},
  {l_jobs, SD_SEND, &l_j, false},      /* the value is copied only if this case is chosen */
  {t_timer, SD_RECV, &t_tick, false},
};
switch (sd_select(cs, 3)) {
case 0: if (!cs[0].ok) l_n = SD_INT_NULL; /* A */ sd_int_release(l_n); break;
case 1: /* B */ break;
case 2: if (cs[2].ok) sd_int_release(t_tick); /* C */ break;
}
sd_chan_release(t_timer);
```

`sd_select` blocks until a case can proceed (there is no default case),
performs it and returns its index; `ok` tells a receive whether a value
arrived (false: closed). When several cases are ready, one is chosen
uniformly at random. A send case on a closed channel crashes if chosen.
Single `send`/`receive` are one-case selects.

**time.** `sd_time_after(ns)` returns a new `chan int` (owned) that receives
the wall-clock time (Unix nanoseconds, `time.now()` in docs/stdlib.md) once,
after `ns` nanoseconds, and is then closed, so a second receive returns null
instead of waiting forever (one timer thread serves all timers).
`sd_time_sleep(ns)` waits (a stopping point for cancellation).
`sd_time_now()` is the monotonic clock in nanoseconds. The compiler exposes
them as `time.after` and `time.sleep`.

## 12. Program entry and exit

```c
static sd_err sd_f_main(sd_list *l_args) { ... }       /* fn main([]string args) error; args borrowed */
int main(int argc, char **argv) { return sd_main(argc, argv, sd_f_main); }
```

`sd_main` sets up stdout buffering (a 64 KB buffer, line-buffered when
stdout is a terminal and fully buffered otherwise; stderr unbuffered), the
crash handlers and the main goroutine, then calls the Seed `main`:

| Outcome | Effect |
|---|---|
| returns null | flush, exit 0 |
| returns an error | flush stdout, `error: <message>` on stderr, exit 1 |
| crashes | defers run, flush stdout, `crash: <message>` on stderr, exit 2 |
| `os.exit(n)` | flush stdout and stderr, exit `n & 255` immediately |
| deadlock | flush stdout, `crash: deadlock: ...` on stderr, exit 2 |

`fmt.eprint`/`eprintln` flush stdout first, so the two streams interleave in
program order. Each `print`/`println` is atomic with respect to other
goroutines.

Constants: package-level `const` values of counted types must not be shared
between goroutines unless immortal. Strings and big integers are (use
`SD_STR_LIT`/`SD_STR_STATIC` and `SD_INT_BIGLIT`). For list/map constants,
build the value where it is used (a fresh owned value each time), or cache it
per goroutine with `_Thread_local` and register a function that releases the
cache with `sd_goroutine_atexit(fn)`: the runtime calls it on the
goroutine's thread when the goroutine ends (never for the main goroutine,
whose caches live until the program exits).

## 13. Native functions

A function or method of a standard library package (a directory under
`$SEED_ROOT/lib`) may be declared without a body. It is then **native**:
written in C, in a `.c` file in the package's directory. This section is the
contract between those C files and the compiler. Elsewhere a missing body is
a compile error (`fn f needs a body`).

```
// lib/fs/fs.sd
pub fn read(string path) (string, error)
pub fn exists(string path) bool

// lib/net/net.sd (an example: a handle type with a private field)
pub type Conn struct {
    int id
}
pub fn (Conn c) read(int max) (string?, error)
pub fn (Conn c) mut setTimeout(int ns)
```

**Where the C goes.** Every `*.c` file directly in the package's directory
(by convention `lib/<pkg>/<pkg>.c`) is pasted into each program that
imports the package, after the runtime, the program's type definitions and
its prototypes, and before the generated functions. Lines starting with
`#include "seed` are dropped (the runtime is already there); system headers
may be included. Name private C helpers `static` and give them the
package's prefix (`net_...`), since every package's C ends up in one file.

**Symbol.** `sd_lib_<path>_<name>` for a function and
`sd_lib_<path>_<Type>_<method>` for a method, where `<path>` is the import
path with `/` replaced by `_`: `fs.read` is `sd_lib_fs_read`, `net.Conn.read`
is `sd_lib_net_Conn_read`. Define it without `static`. The compiler emits a
prototype for it from the Seed declaration, so a C definition that does not
match the declaration is a C compile error. (The compiler calls it through
a generated wrapper `sd_f_fs_read` with the usual calling convention, so a
native can also be used as a function value, deferred or spawned.)

**Parameters** use the C type of section 2 and are **borrowed** (section
3): never release them; retain what you keep. A receiver comes first: by
value (borrowed) for a plain method, as a pointer to the caller's variable
for a `mut` method (change it in place; make containers unique first with
`sd_list_mut`, `sd_box_mut`, ...). A struct type `T` of package `p` is the C
struct `sd_S_p_T` (`sd_S_net_Conn`), with one member `f_<field>` per field
(`c.f_id`), whatever the fields' visibility in Seed.

**Results** are **owned** (+1):

| Seed result | C |
|---|---|
| none | `void` |
| `T` | returns `T` |
| `T?` | returns the nullable representation of section 2: `NULL` for strings, lists, maps, channels and `S?` boxes, `SD_INT_NULL`, `(sd_opt_float){false, 0}`, `SD_IFACE_NULL` |
| `(A, B, ..., E)` | returns the **last** result; the others come back through out-pointers **appended after the parameters**, in order |

```c
sd_err sd_lib_fs_read(sd_str path, sd_str *out);                     /* (string, error) */
sd_err sd_lib_os_run(sd_list *argv, sd_int *code);                   /* (int, error) */
sd_err sd_lib_net_Conn_read(sd_S_net_Conn c, sd_int max, sd_str *out); /* (string?, error) */
void sd_lib_net_Conn_setTimeout(sd_S_net_Conn *c, sd_int ns);         /* mut method */
```

The out-slots are initialised to null (or zero) before the call. When a
native returns a non-null error, it should leave them that way (or store
nulls): the caller never reads or releases them (`try`, the error guards).
Anything stored in an out-slot is owned by the caller.

**Errors** are `sd_err` values made with `sd_errorf` (or `sd_errors_new`).
Their messages follow docs/stdlib.md: `<package>.<function>: <subject>:
<reason>`, with a lowercase reason; `sd_strerror(errno)` gives the system's
reason in that form:

```c
sd_err sd_lib_fs_read(sd_str path, sd_str *out) {
  FILE *f = fopen(path->data, "rb");
  if (!f) return sd_errorf("fs.read: %s: %s", path->data, sd_strerror(errno));
  ...
  *out = sd_str_new(buf, n);
  return SD_ERR_NULL;
}
```

**Crashes.** A caller's mistake (docs/stdlib.md, "Errors and crashes") is
`sd_crash("rand.range: lo (%lld) must be less than hi (%lld)", ...)`, which
never returns; it crashes the calling goroutine like a runtime fault. Seed
code does the same with `os.crash(message)`.

**Strings** are `sd_str` (`s->data` is NUL-terminated, `s->len` bytes, and
may contain NULs): make them with `sd_str_new(bytes, n)` or
`sd_str_from_cstr`. Ints are `sd_int`: `sd_int_to_i64(v, &i)` (false when
it does not fit), `sd_int_from_i64(i)`. Lists: `sd_list_new(&sd_type_str,
cap)`, `SD_LIST_PUSH(&l, sd_str, value)`, `SD_LIST_GET(l, T, i)`.

**Blocking calls.** Each goroutine runs on an OS thread, so a native that
blocks blocks only its own goroutine. To be a **stop point** (SPEC.md,
DECISIONS.md, "Concurrency": a goroutine whose group fails must stop there too), a
native never blocks in the OS directly; it waits through the runtime:

```c
int sd_wait_fd(int fd, bool for_write, int64_t timeout_ns);  /* <= 0: no limit */
    /* SD_WAIT_READY, SD_WAIT_TIMEOUT, SD_WAIT_STOP, SD_WAIT_FAILED (errno) */
int sd_wait_child(pid_t pid, int *status);  /* 0, an errno value, or SD_WAIT_STOP */
bool sd_stopping(void);
SD_NORETURN void sd_stop(void);
```

`sd_wait_fd` `poll`s the descriptor together with the goroutine's
**wake-up pipe** (made on its first wait, closed when the goroutine is
freed). Cancelling a goroutine sets its flag and, if it is waiting, writes
a byte to the pipe, so the wait returns `SD_WAIT_STOP` at once. The native
then releases what it holds (closes a half-made socket, frees memory) and
calls `sd_stop()`, which unwinds the goroutine exactly like a cancelled
channel operation (defers run; C locals of the unwound frames leak, as for
any crash). A wait in an already cancelled goroutine returns `SD_WAIT_STOP`
without waiting, so a deferred call of a stopped goroutine that blocks is
stopped too (as a channel operation would be). `sd_wait_child` waits for a
child process (a helper thread does the blocking `waitpid` and signals a
pipe); on `SD_WAIT_STOP` it has already killed the child with `SIGKILL`
and reaped it. `os.run` uses it, so it is a stop point. A goroutine
waiting in `poll` counts as running for the deadlock check: something
outside the program can still wake it. If no descriptors are left for the
wake-up pipe, waits poll in slices of 50 ms instead and still notice a
stop. (docs/stdlib.md sketched a pair `sd_block_begin`/`sd_block_end`
around a native's own wait; a single call that does the waiting is harder
to get wrong, and a native with an unusual wait can still use `sd_wait_fd`
on a pipe of its own, as `sd_wait_child` and `net.dial`'s name lookup do.)

```c
/* a native that waits for a socket to become readable */
int w = sd_wait_fd(fd, false, timeout_ns);
if (w == SD_WAIT_STOP) { free(buf); close(fd); sd_stop(); }   /* never returns */
if (w == SD_WAIT_TIMEOUT) return sd_errorf("net.dial: %s: timeout", addr->data);
```

**Handles.** Open descriptors that Seed code refers to (connections,
listeners, files, stdin) live in one process-wide table; the Seed handle
type holds only the entry's id (`pub type Conn struct { int id }`). Ids
count up from 1 and are never reused.

```c
int64_t sd_handle_new(int kind, int fd, const char *name);  /* SD_HANDLE_CONN, _LISTENER, _FILE, _STDIN */
sd_handle *sd_handle_acquire(int64_t id, int kind);         /* NULL: closed, unknown or another kind */
void sd_handle_release(sd_handle *h);
bool sd_handle_close(int64_t id);                           /* false: already closed */
void sd_handle_set_timeout(int64_t id, int64_t ns);
sd_str sd_handle_subject(int64_t id);                       /* its name, "" once closed */
int sd_handle_wait(sd_handle *h, bool for_write);           /* SD_IO_OK, _TIMEOUT, _CLOSED, _ERROR */
int sd_handle_read(sd_handle *h, int64_t max, sd_str *out, int *err);
int sd_handle_read_line(sd_handle *h, sd_str *out, int *err);
int sd_handle_read_all(sd_handle *h, sd_str *out, int *err);
int sd_handle_write(sd_handle *h, const char *data, int64_t len, int *err);
sd_err sd_handle_error(const char *fn, const sd_handle *h, int kind, int result, int err);
```

- `sd_handle_acquire` takes the entry's **operation lock**, so each
  operation is atomic; a second goroutine using the same handle waits for
  it (a stop point, checked every 20 ms). Release it with
  `sd_handle_release` on every path.
- The I/O functions return `SD_IO_OK` (a read got at least one byte),
  `SD_IO_EOF` (nothing: end of input), `SD_IO_ERROR` (the errno value in
  `*err`), `SD_IO_TIMEOUT` (no progress within the handle's timeout) or
  `SD_IO_CLOSED`. They wait with `sd_handle_wait`, which **stops the
  goroutine itself** (releasing the handle first) when it is cancelled, so
  a native must hold nothing else across them. `sd_handle_error` turns a
  result into the docs/stdlib.md error, `"<fn>: <name>: <reason>"`
  (`timeout`, `connection is closed`, `listener is closed`, `file is
  closed`, or `strerror`).
- Reads go through the entry's buffer, so `read_line`, `read` and
  `read_all` can be mixed (lines end at `"\n"`, with a `"\r"` before it
  removed; the last line may lack the `"\n"`). A non-blocking descriptor
  is read first and polled on `EAGAIN`; a blocking one (stdin, which may
  be shared with other processes) is always polled first, so that the
  wait stays a stop point. Writes to a `SD_HANDLE_CONN` use `send` without
  `SIGPIPE`.
- `sd_handle_close` marks the entry closed, takes it out of the table and
  wakes a goroutine waiting on it (through its wake-up pipe), which gets
  `SD_IO_CLOSED`. The descriptor itself is closed when the last operation
  using it releases it, so its number is never reused under a running
  operation. Handles are not closed when the last Seed copy disappears;
  the process's exit closes them.

`lib/io/io.c` and `lib/net/net.c` are the examples to follow.

**What the compiler knows.** Nothing about natives beyond their
declarations, except that `os.exit` and `os.crash` never return (for
"missing return" and unreachable code).

The core packages are written this way: `lib/fmt`, `lib/os`, `lib/fs` and
`lib/time` declare their functions native and call the runtime functions of
section 14 (`sd_lib_fmt_println` calls `sd_fmt_println`); `lib/errors` is
plain Seed.

condition variable, several microseconds on macOS). `park` therefore spins
on the goroutine's wake flag for up to 20 us first, when there are idle
CPUs (fewer running goroutines than CPUs) and fewer than half the CPUs are
spinning already; a hand-off that arrives meanwhile costs neither the
signal nor the wake-up. Buffered channels avoid parking when they don't
fill up. The `group` and worker-pool locks are taken with a short
`trylock` loop before blocking, since many threads take them at once when
goroutines start and end in bursts. bench/ and docs/performance.md compare
whole programs with Go.

## 16. Decisions and limitations

Decisions made while writing the runtime (nobody was available to ask):

1. **Tagged ints** with 63-bit small values; big values are sign-magnitude
   with 32-bit limbs, schoolbook multiplication and Knuth division (fine for
   a compiler; no Karatsuba).
2. **Struct `sd_int`**, not a bare `int64_t`, so that mixing raw C integers and
   Seed ints is a compile error in generated code.
3. **Ownership: borrow arguments, own results, stores consume.** This makes
   temporaries cheap (`parts.push(x.string())` moves the new string in) and
   reading variables free.
4. **Strings are single pointers** (no substring sharing): `slice` copies.
   One-byte strings and `""` are preallocated immortal objects, so `chars()`
   on ASCII allocates only the list.
5. **Lists store elements inline** after the header (one allocation).
6. **Copy-on-write test is `rc != 1`**, so immortal containers are copied
   before any write.
7. **Deep copy on send happens once, by whichever side completes the
   transfer**, under the channel lock. Immortal objects and channels are
   shared instead of copied.
8. **Goroutines are OS threads** with 8 MB (lazily committed) stacks,
   reused by later goroutines (section 10). The runtime keeps a count of
   running goroutines to detect deadlocks.
9. **Cancellation points are send, receive, select, sleep and the blocking
   calls of section 13** (handle I/O, `sd_wait_fd`, `sd_wait_child`), not
   `close`; cancelled goroutines run their defers; a channel operation or
   blocking call inside a defer of a stopped goroutine stops that deferred
   call (the other defers still run).
10. **First crash wins** when deferred calls crash during unwinding.
11. **Crashes unwind with `siglongjmp`**; stack overflow and other memory faults
    are caught with a SIGSEGV/SIGBUS handler on an alternate stack and
    reported as crashes (disabled under sanitizers, which have their own).
12. **Errors compare by message** (seed0's rule); interfaces compare by dynamic
    type and value.
13. **`main` crashes run defers** before printing `crash:` (as Go does).
14. **`os.exit(n)`** uses `n & 255`; it doesn't run defers.
15. **time.after** delivers the wall-clock time (an `int`, Unix nanoseconds)
    once on a channel with a buffer of one, and then closes the channel (as
    docs/stdlib.md specifies; it used to send the monotonic time and stay
    open).
16. **Freeing never recurses.** (Added with the compiler's switch to this
    runtime, as a bug fix: dropping a 100,000-node linked list of
    `Node? next` boxes overflowed the stack.) A box, list or map whose
    count drops to zero while another one is being freed is queued (through
    its dead count field) and freed by the outermost release, so dropping
    long chains or deep trees uses constant stack (`sd_free_queued_` in
    `seed_core.c`; `test_mem.c` frees a million-node box chain, list nesting
    and map nesting).

17. **Blocking calls wait in `poll` with a per-goroutine wake-up pipe**
    (section 13) rather than with signals (`pthread_kill` + `EINTR` races
    with the call being entered) or an event loop (goroutines are threads).
    It costs two descriptors per goroutine that ever blocks.
18. **Finished goroutines are reaped at the next spawn** in their group
    (section 10), so long-running groups don't keep their tasks.
19. **Worker threads are reused** (section 10) rather than one thread being
    created and joined per goroutine: starting a goroutine went from about
    15 us to 1.4 us. Only threads whose goroutine returned are reused.
20. **Spinning before sleeping** (section 15), bounded to half the CPUs
    and to times when CPUs are idle, for parked goroutines (20 us) and idle
    workers (20 us). An unbuffered round trip went from 3.3 us to 0.7 us.

Limitations and things left for later:

- **A crash or cancellation leaks the counted values held in the locals of the
  unwound C frames** (defer environments are released). A long-running program
  that crashes many goroutines loses that memory. Fixing it needs generated
  code to register its locals; section 17 has the design, and why a
  runtime-only fix was measured and not kept.
- Big integers use quadratic algorithms; `int.string()` of a number with
  millions of digits is slow.
- Each running goroutine is a thread: tens of thousands of simultaneous goroutines
  will hit OS limits (`ulimit -u`, kernel thread limits); `sd_spawn` ends the
  program with `crash: cannot start a goroutine (out of threads)` when
  thread creation fails.
- Package-level constants of list/map type must not be cached in shared
  memory (section 12).
- Two goroutines using one handle at once take turns on its operation lock;
  the one waiting checks for a stop every 20 ms rather than being woken.
- A goroutine stopped in a blocking call leaks its C frames' locals, like
  any crash or cancellation.
- Tested on macOS (arm64, Apple clang). The code uses only C11 and POSIX
  (`pthread`, `posix_spawnp`, `sigaltstack`, `clock_gettime`); Linux was not
  available for testing. On glibc, `posix_spawnp` may report a missing program
  as exit status 127 rather than an error.

## 17. Future work

### Freeing what an unwound frame held

A crash, or a goroutine stopped at a stop point, unwinds with
`siglongjmp`, which skips the releases the generated code would have done
on the way out of each frame. The defers run and their environments are
released, the goroutine's arguments are released, but every counted value
that only a C local of an unwound frame (or an owned temporary) held is
leaked. A server whose handlers crash on bad input loses memory with each
crash; one that stops connection goroutines at shutdown loses what they
held. Normal execution leaks nothing.

Three ways to fix it were considered; the measurements are from this
machine (Apple M-series, `-O2`).

**1. A registry of the objects each goroutine owns (runtime only; built,
measured and not kept).** Goroutines share nothing, so when a goroutine
crashes or is stopped, every object it still owns once its defers have run
is garbage. A prototype kept, per spawned goroutine, an open-addressing
hash set of the objects allocated while it ran (`sd_obj_alloc` adds,
`sd_obj_free` removes, `realloc` moves); copies made for another goroutine
(channel transfers, spawn arguments) were made outside it and adopted by
the receiver; channels and immortal objects were never tracked. At the end
of a crashed goroutine the remaining objects were made immortal (so that
releases between them do nothing), the references they held to untracked
objects were released, and then they were freed. It worked: the runtime
tests freed everything except channels held only by unwound locals,
`make test-leaks` reported the crashing goroutines of `group_crash`,
`os_stop_points` and `fs_file_stop` clean, and the soak found no problem.
It also needed `sortBy` to sort a copy (a `less` that crashes halfway
otherwise leaves an element duplicated in the list, which the sweep would
release twice). But it cost every allocation and every free in any program
that has spawned a goroutine: on an allocation-heavy goroutine (the json,
strings and maps benchmarks run inside one `spawn`) **+18% for the
thread-local lookup alone** (`_Thread_local` is a call to `tlv_get_addr`
on macOS) **and +80% in total** with the set (1.13 s to 2.05 s; with a
million live objects the set is 16 MB and nearly every insert and delete
misses the cache). An intrusive list or a per-object index in a hidden
header would avoid the set's misses but adds 8 to 16 bytes to every
object, and the thread-local lookup remains. Too expensive to make the
price of a feature that only matters after a crash.

**2. Unwinding by returning (compiler).** Generated code would test a
per-goroutine "unwinding" flag after every call that can crash and leave
through the function's normal exit path, which already releases the
locals (as `try` does). Precise, with no memory overhead and a well
predicted branch after each call (a few percent), but every runtime
function that crashes would have to return instead, and every expression
would need an exit path: a large change to the code generator and the
runtime API.

**3. Cleanup frames on the defer stack (compiler; recommended).** The
runtime already keeps a per-goroutine cleanup stack that the unwinder
walks (defers and groups, `sd_cleanup` in `seed_task.c`). A third kind of
entry, a frame of counted locals, makes unwinding release them:

- Runtime (small, can be added at any time): `size_t
  sd_frame_push(void *locals, const sd_type *desc)` pushes an entry
  `{locals, desc}` and returns the mark; `void sd_frame_pop(size_t mark)`
  drops it without running anything (normal exit). When `unwind_to` meets
  such an entry it calls `sd_release(desc, locals)`, which releases every
  counted field. Entries need no arena space.
- Compiler: in a function that has counted locals or owned temporaries
  (strings, lists, maps, boxes, interfaces, errors; `int` can be left out,
  see below), declare them as fields of one local struct
  `struct { sd_str l_name; sd_list *l_xs; sd_str _t3; } L = {0};` with a
  generated `SD_STRUCT_TYPE` descriptor listing those fields, call
  `size_t fm = sd_frame_push(&L, &D_fn_locals)` on entry, and
  `sd_frame_pop(fm)` before every `return` (before `sd_defer_run`, whose
  mark is below it). The one invariant: **at every point where a crash or
  a stop can happen, each field holds either null or a value it owns.**
  That means three local rules on top of today's code: a field is set to
  null right after it is released or moved out (`return x`, a store that
  consumes it, passing it to a consuming runtime function), temporaries
  live in fields too, and a field is only assigned after its old value has
  been released (already the order the generator uses).
- Cost: a frame push and pop (a few stores, no allocation) per call of
  such a function, and its locals live in memory rather than registers
  across calls. Functions with only scalars (and `int`s, if left out) pay
  nothing, so `fib` and the integer loop are unaffected; functions that
  handle strings or lists already pay for allocation, which dwarfs this.
  Leaving `int` out means a crash still leaks the big integers held by
  locals, which are rare.
- With this in place the leak tests can drop their `.leaks` files, and
  `sortBy` needs the copy-then-write-back sort described in 1 (the
  prototype's change to `list_sort` in `seed_list.c`).
